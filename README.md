# Вишлист v9 — общая база для всех пользователей

В этой версии товары больше не хранятся только в `localStorage`. Общий список, описания, фотографии и статус «забронировано» хранятся в Supabase. Изменения приходят другим открытым страницам через Supabase Realtime.

## 1. Создай Supabase project

Открой https://supabase.com/ и создай проект.

## 2. Создай таблицу

В Supabase открой **SQL Editor**, вставь весь файл `supabase_setup.sql` и нажми Run.

SQL создаёт таблицу `wishlist_products`, RLS-политики и подключает таблицу к `supabase_realtime`. Supabase требует, чтобы таблицы были добавлены в realtime publication для Postgres Changes.

## 3. Заполни ключи

В Supabase открой **Project Settings → API** и возьми URL проекта и publishable/anon key.

Открой `supabase-config.js` и замени:

```js
window.SUPABASE_CONFIG = {
  url: "https://YOUR-PROJECT.supabase.co",
  anonKey: "YOUR_PUBLISHABLE_OR_ANON_KEY"
};
```

Не вставляй `service_role` key в браузерный файл.

## 4. Загрузи проект на Vercel

Сделай новый Deploy проекта. В проект уже включён CDN Supabase JS, поэтому устанавливать npm-пакет не нужно.

## Что теперь синхронизируется

- добавление товара;
- удаление товара;
- название, описание и фото;
- ссылка;
- магазин;
- статус «Забронировано»;
- изменения видны другим открытым страницам почти сразу.

## Перенос старой версии

При первом открытии новой версии браузер попробует один раз перенести товары из старого `localStorage` в Supabase. Уже существующие записи не дублируются.

## Важно про права

В этой простой версии сайт разрешает анонимным посетителям читать, добавлять, изменять и удалять записи. Это удобно для общего вишлиста, но означает, что любой посетитель технически может изменить список. Если нужно, следующей версией можно сделать вход владельца для добавления/удаления, а гостям оставить только просмотр и бронь.
